# Архитектура и безопасность

## Модули и данные

- `app/etl.py`: распознавание CSV, типы, nullable поля, проверка флагов, идемпотентность по файлу и версии pipeline, upsert, журнал конфликтов. Три CSV импортируются последовательно: компании, связи, платежи.
- `app/pdf_extract.py`: извлечение текста, локальный OCR сканов. `app/search.py`: русскоязычный Full-Text Search через GIN. Запросы параметризованы.
- `app/profiles.py`: признаки компании, продукты и ограниченный SQL-граф из платежей, группы и общих физических лиц; сохранение неизвестных концов связей.
- `app/news.py`: RSS, безопасное получение URL, категории, сохранение оригинальных текстов/анонсов, нормализация заголовка/URL.
- `app/ranking.py`, `config/ranking.json`: прозрачные настраиваемые баллы. Отрасль/география/продукты/ФТС/контрагенты/группа/наличие выручки/роль/банковский поиск. Наличие выручки даёт небольшой сигнал полноты данных, а не оценку рыночного масштаба при неизвестной единице.
- `app/agent.py`: собственный контекстный план и реальные инструменты. При отсутствии связей этот шаг пропускается. При пустом поиске банк-материалов добавляется расширенный запрос. Результаты предыдущих шагов сохраняются и используются далее.
- `app/llm.py`: Provider, DisabledProvider, тестовый провайдер только для тестов, адаптер подтверждённого API. Дневные резервы и учёт токенов.
- `app/main.py`: REST, проверка доступа, лимиты, CRUD события, анализ, вопросы, документы, метрики и раздача собранного React.

Таблицы: companies, person_links, payments, articles, bank_documents, document_chunks, agent_runs, agent_steps, feedback, llm_usage, import_batches, data_issues. Отдельная сущность события объединена с article, итоговый insight/evidence — структурированный JSON в agent_run. Это сокращает схему без потери трассы. Демонстрационные пользователи представлены Principal и токенами; полноценная таблица users и SSO не реализованы.

Alembic: 0001 — базовая схема/индексы, 0002 — сохранение ссылок на отсутствующие профили, 0003 — аудит противоречащих строк. Применение с нуля проверяется в пустой схеме PostgreSQL. Downgrade 0002 намеренно блокируется до сверки отсутствующих профилей, чтобы откат не удалял исходные связи.

## Агент и доказательства

План строится по известному контексту и реальной доступности модели; инструментов максимум 16, общий бюджет времени 90 секунд, запрос LLM до 35 секунд. Сохраняются задача, план, выполненные инструменты, краткий результат, время, evidence и проверка. Скрытые рассуждения модели не запрашиваются и не отображаются.

В режиме правил риски и действия — условные проверки с опорой на профиль и событие. Банковские цитаты не переименовываются в экспертное заключение по новой новости. При LLM генерация происходит только после извлечения профиля, связей и документов; ответ валидируется по схеме, IDs и числам. Некорректный ответ отклоняется, ошибка фиксируется, сохраняется честный разбор по правилам. Глубокое семантическое подтверждение требует эксперта и отдельной оценки.

Технический успех запуска не означает бизнес-качество. Тестовые ответы имеют отдельный mode=test и не выбираются для интерфейса автоматически.

## Доступ

Проверка на сервере: Principal демо — только synthetic компании; Principal администратора — официальные профили, документы и импорт. Каждый доступ к разбору, источникам, шагам, вопросам и feedback заново проверяет компанию. Поиск банка для synthetic компании использует только synthetic документы, поэтому публичный демо-сценарий не раскрывает локальные PDF.

Сейчас это одна изолированная демонстрационная область из трёх компаний, а не многопользовательская банковская среда. Роли CEO/CFO/казначейство/бухгалтер меняют информационный приоритет, не эмулируют промышленный ACL. Для внешнего production нужны пользователи, membership компании, SSO/JWT, аудит и отзыв токенов.

## Внешние источники

URL: только HTTPS и явный список новостных хостов, порт 443, без userinfo. Разрешение DNS проверяется на глобальность всех адресов, redirects и системные прокси отключены, лимит ответа 2 МБ, timeout 15 секунд. Поддерживается ручной текст для других источников; авторизация и платный доступ не обходятся.

Остаточный риск DNS rebinding между проверкой DNS и соединением описан явно: перед публичным размещением нужен outbound proxy с закреплением адреса/сетевой allowlist. Текущая мера не заявляется полной защитой от всех сетевых атак.

Новости и документы — недоверенные данные. HTML очищается BeautifulSoup и отображается React как текст, `dangerouslySetInnerHTML` не используется. Модель не получает секреты, shell или произвольные сетевые инструменты. Изменения данных делает ограниченный серверный код.

Секреты в .env/окружении, исключены из Git/образа/контекста модели. Заголовки nosniff, DENY и no-referrer. API записи ограничены 20 запросами в минуту на IP и путь в одном процессе. Это защита прототипа, не распределённый rate limiter. Импорт только администратору, до 12 МБ через HTTP. CLI предполагает доверенную локальную работу.

## Масштабирование и сопровождение

Фактически загружено более 1.38 млн платёжных строк, есть индексы концов связей, company group и дат новостей. Стриминговые CSV читаются в памяти файла с пакетной записью по 700 строк; это воспроизводимый прототип, не бесконечный поток. Ограничения выдачи и графа отражены API и README.

Следующие этапы: фоновые задания с очередью и отдельными workers; инкрементальный refresh; устойчивые source adapters и лимиты на источник; материализованные признаки связей и кеш ранжирования; отдельные рабочие области клиентов; latency/error dashboards; экспертный golden set. Промышленное нагрузочное тестирование не выполнено.
