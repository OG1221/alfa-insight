# Подключение разрешённой LLM

На 22 октября 2026 API организаторов не предоставлен. Ни endpoint, ни API model ID, ни тариф не известны. Реальная генерация не тестировалась. Поддерживаемый в коде протокол — OpenAI-compatible Chat Completions с Bearer-токеном, JSON-ответом и usage. Это подготовленный адаптер, а не подтверждение формата организаторов.

## Что получить у организаторов

1. Базовый HTTPS URL и документацию авторизации.
2. Точный model ID и его соответствие одному из шести разрешённых наименований.
3. Подтверждение протокола, пути `/chat/completions`, `response_format` и формата usage.
4. Стоимость входных и выходных токенов, лимиты и поддержку Idempotency-Key.
5. Ключ доступа. Не присылайте его в открытые каналы и не сохраняйте в Git.

Разрешённые наименования: Gemma 4 26B A4B; GLM-5.3-Flash; Qwen3.6 35B A3B; DeepSeek-V4.1-Flash; Qwen3-VL-30B-A3B-Instruct; Kimi-K2.6. Других моделей в приложении нет. Отображаемое имя и API ID могут различаться: соответствие должен подтвердить организатор, не модель и не эвристика кода.

## Конфигурация

Скопировать `.env.example` в `.env`, заполнить только подтверждённые значения:

```dotenv
LLM_MODE=production
LLM_API_KEY=
LLM_BASE_URL=
LLM_MODEL=
LLM_APPROVED_NAME=
LLM_PROTOCOL=openai-chat
LLM_MAX_TOKENS=1800
LLM_TIMEOUT=35
LLM_DAILY_BUDGET_RUB=500
LLM_INPUT_RUB_PER_MILLION=0
LLM_OUTPUT_RUB_PER_MILLION=0
```

Нулевые тарифы, HTTP вместо HTTPS, неизвестное имя разрешённой модели и неподтверждённый протокол блокируют запросы. Если предоставленный API не совместим, реализовать отдельный Provider в `backend/app/llm.py`, сохранив схему ответа и бюджетный контроль. Не пытаться угадать адреса или запускать другую модель.

Перезапустить сервер. `/api/status` показывает состояние конфигурации, не факт успешного вызова. Реальный readiness подтверждается следующим этапом.

## Проверка реальной интеграции

1. Сначала выполнить backend-тесты: контракт, негативные исходы, сохранение резерва, запрет бюджета.
2. На разрешённом синтетическом профиле добавить новую учебную новость.
3. Открыть разбор. Убедиться, что `mode=llm`, `generation_error=null`, есть фактический шаг `generate_interpretation` и валидные ссылки.
4. Проверить в `llm_usage` model ID, токены, дату и стоимость; убедиться, что провайдер не заменил модель.
5. Экспертно сверить каждое утверждение с указанными фрагментами. Автоматические проверки охватывают только ID источников и присутствие чисел в указанных доказательствах.
6. Задать уточняющий вопрос, проверить его источники.
7. Проверить неизвестную новость, конфликт источников, отсутствие банковского документа и недоступность API.
8. Сохранить обезличенный отчёт в `docs/verification.md`, без ключей и содержимого приватного профиля. Только после этого указывать «проверено с реальной LLM».

## Бюджет

В `llm_usage` сохраняется консервативный резерв перед сетевым вызовом. Вход оценивается с верхней границей по UTF-8 байтам плюс служебный запас, выход — по `LLM_MAX_TOKENS`; PostgreSQL advisory lock исключает одновременное резервирование сверх дневного лимита. Дата бюджета — Europe/Moscow. Ограничение — минимум из 500 ₽ и пользовательского лимита.

При валидном usage резерв заменяется расчётной стоимостью. При неизвестном результате оплаты резерв остаётся, чтобы сбой не позволял повторно расходовать бюджет. Один безопасный повтор после HTTP 429 с backoff; ошибки соединения и HTTP 5xx автоматически не повторяются. Изменение тарифов и фактический биллинг провайдера нужно сверять отдельно. Приложение не может гарантировать внешний лимит провайдера, если его тарифы настроены неверно.

## Проверяемость и инъекции

Профиль, новость и цитаты передаются как JSON с явной системной инструкцией трактовать их как данные. Ключи и конфигурация не включаются в контекст. Модель не получает средства исполнения кода, произвольного HTTP или изменения базы. Каждый результат валидируется по `GeneratedInsight`; неизвестные evidence IDs и числа без опоры отклоняются, приложение показывает честный разбор по правилам с сообщением ошибки.

`TestProvider` доступен через явное внедрение только в автоматических тестах; он помечает результат `test` и не переключается в пользовательский AI-режим переменной среды.
