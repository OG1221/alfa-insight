# Подключение LLM

В приложении реализован адаптер OpenAI Chat Completions. Для подключения нужны подтверждённые адрес API, технический ID модели, ключ и тарифы. Список разрешённых моделей:

- Gemma 4 26B A4B
- GLM-5.3-Flash
- Qwen3.6 35B A3B
- DeepSeek-V4.1-Flash
- Qwen3-VL-30B-A3B-Instruct
- Kimi-K2.6

Веса моделей не входят в поставку. Технические model ID зависят от API; их нельзя заменять похожим названием. Если сервер использует другой протокол, нужен отдельный адаптер `Provider`.

## Настройка

Заполните серверный `.env`:

```dotenv
LLM_MODE=production
LLM_BASE_URL=
LLM_API_KEY=
LLM_MODEL=
LLM_APPROVED_NAME=
LLM_PROTOCOL=openai-chat
LLM_INPUT_RUB_PER_MILLION=
LLM_OUTPUT_RUB_PER_MILLION=
LLM_DAILY_BUDGET_RUB=500
```

`LLM_APPROVED_NAME` — точное название из списка выше. `LLM_MODEL` — ID, принимаемый сервером. Тарифы задаются в рублях за миллион входных и выходных токенов. Сервис откажется от запроса без обязательных параметров или при превышении бюджета.

Ключ хранится на сервере. Он не передаётся в браузер, контекст модели или Git.

## Проверка

```sh
python scripts/check_llm.py
python scripts/check_llm.py --run
```

Первая команда проверяет настройки. Вторая делает реальные запросы в пределах бюджета и сохраняет результат в `runtime/llm-acceptance.json`. Успешная настройка сама по себе не подтверждает работу API: итоговый режим должен быть `llm`, а цитаты — пройти проверку.

При ошибке API, некорректном JSON или неподтверждённых выводах приложение сохраняет разбор по правилам и причину отказа. Реальная генерация и её смысловое качество требуют отдельной проверки после выдачи доступа.
