# Внешнее развёртывание

Публичный URL **не создан**. На этой машине Docker отсутствует, аккаунт/сервер для Python + PostgreSQL не предоставлен. Sites поддерживает Cloudflare Workers, но не исполняет этот FastAPI/PostgreSQL стек с прямым TCP. Публикация одного интерфейса без API не является рабочим развёртыванием и не выполнялась.

## Воспроизводимая подготовка

1. Проверить `docker compose config`, `docker compose build`, `docker compose up`, healthchecks и весь пользовательский путь на машине с Docker. Проверить ARM64 либо целевую x86_64 архитектуру.
2. Выбрать уже доступный бесплатный/оплаченный Linux-сервер с Docker и постоянным диском. Не подключать платный тариф без отдельного согласования. Конкретный текущий бесплатный тариф не заявляется и не проверялся.
3. Передать репозиторий и **только синтетический набор**. Не копировать `.env`, `runtime`, `data/private` и реальные банковские материалы на публичный стенд без подтверждённых прав.
4. Сгенерировать случайные ADMIN_TOKEN, DEMO_TOKEN и пароль PostgreSQL. Секреты в окружении/хранилище хостинга. Отключить анонимный доступ при использовании чувствительных данных, добавить полноценный вход и membership ACL до такого размещения.
5. Сохранить binding приложения `127.0.0.1:8000`. Перед ним — reverse proxy с HTTPS, явными hostnames, ограничением размера запроса и timeout. PostgreSQL не публиковать наружу.
6. Добавить outbound proxy/сетевую allowlist для безопасной загрузки новостей и доступа к подтверждённому LLM API. DNS-проверки приложения не заявляются полной защитой против rebinding.
7. Запустить Compose, проверить `/api/health`, готовность базы, import синтетических данных, создание новой новости, анализ, отрицательные проверки авторизации, источники и поведение без ключа.
8. Открыть реальный HTTPS URL в браузере и повторить сценарий на широком и мобильном экранах. Только после успеха записать URL в README/verification.

## Резервирование и сопровождение

PostgreSQL — volume `pgdata`; делать регулярный `pg_dump`, проверять восстановление. Не удалять volume командой `down -v` на рабочем стенде. Логи не должны содержать Bearer-токены или LLM ключи. Публиковать только версии с успешными проверками и фиксированным commit hash.
