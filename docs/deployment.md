# Развёртывание

## Docker Compose

```sh
docker compose up --build -d
docker compose ps
```

Приложение слушает `127.0.0.1:8000`. Порт меняется через `APP_PORT`. PostgreSQL не публикуется наружу и хранит данные в volume `pgdata`.

Миграции применяются перед запуском API. Синтетические данные загружаются при `DEMO_MODE=true`. Официальный набор импортируется отдельно по инструкции в README.

## Внешний сервер

Для размещения нужны Docker, постоянный диск и HTTPS reverse proxy перед приложением.

1. Задайте собственные `ADMIN_TOKEN`, `DEMO_TOKEN` и `POSTGRES_PASSWORD`.
2. Храните `.env` и ключ LLM в секретах сервера, отдельно от кода.
3. Ограничьте доступ к официальным данным. Для многопользовательской работы добавьте пользователей и права на компании.
4. Настройте HTTPS, лимиты запросов и исходящий сетевой allowlist.
5. Проверьте `/api/health`, создание новости, разбор, источники и отказ неавторизованного доступа.

Изменение `POSTGRES_PASSWORD` в Compose не меняет пароль уже созданной базы. Резервные копии делаются через `pg_dump`; восстановление следует проверять отдельно.

`docker compose down` останавливает сервисы и сохраняет данные. Добавление `-v` удаляет volume и предназначено только для ненужной тестовой базы.
