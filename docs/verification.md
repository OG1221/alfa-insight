# Фактическая проверка локальной версии

Дата: 22 октября 2026, Europe/Moscow. Среда: macOS ARM64, Python 3.12, локальный PostgreSQL 14, встроенный Node 24, установленный Google Chrome. Отчёты остаются в `runtime/` и не попадают в публичный репозиторий.

## Проверено

Итог: **42 backend-теста, 8 E2E desktop/mobile**, сборка TypeScript/Vite и реальный HTTP smoke. Все успешно; один deprecation warning TestClient.

- Миграции Alembic 0001–0004 применены к рабочей базе и отдельно с нуля в пустой тестовой схеме; создан GIN-индекс русскоязычного поиска.
- Официальные CSV импортированы; повторный неизменный файл пропускается. Противоречащие повторы компаний и платёжных пар не скрываются. Ссылки на отсутствующие профили сохранены.
- Все 9 PDF извлечены через локальное OCR: 64 страницы, 172 фрагмента. Визуально сверена страница обзора ставки, все страницы официального задания просмотрены обзором; полного построчного контроля OCR всех банковских страниц нет.
- Приоритет оригинального PDF для события с известной исходной ссылкой проверен отдельным тестом; это предотвращает вытеснение первоисточника похожим архивным обзором.
- Два RSS вернули реальные записи: Банк России и Интерфакс. Повторный refresh не дублировал те же заголовки.
- Сборка TypeScript/Vite завершена. Python compileall, pip check, shell syntax и git diff --check проходят.
- `scripts/start-local.sh` действительно применил миграции, собрал frontend, запустил API и сайт. `/api/health` вернул PostgreSQL / ok.
- Одинаковое архивное событие обработано для U_9250 и U_57706: оценки и основания различаются, кредитный контекст не переносится на компанию без кредитного признака, депозитный вывод появляется у компании с депозитом. По обоим профилям найдены реальные банковские фрагменты и записаны выполненные инструменты. Это проверка правил, не оценка LLM.
- Backend-тесты используют отдельные схемы PostgreSQL, включая реальные HTTP-контрактные заглушки LLM: импорт, UTF-8/cp1251, пропуски, конфликтующие строки, неизвестные контрагенты, profiles, news dedup, ranking, search, adaptive plan, step limit, API ACL, feedback, SSRF, schema validation, unavailable dialog, bad provider output, budget reservation and refusal, wrong model, metrics refusal without labels.
- 8 Playwright-сценариев desktop/mobile: обзор, выбор компании, профиль, фильтры, разбор, источники, журнал, отключённый AI-диалог, добавление ранее неизвестной новости, понятная SSRF-ошибка, официальный доступ и поиск банка, отсутствие горизонтального переполнения и JS pageerror в основном сценарии.

Первая серия E2E: 7 прошли, 1 упал на проверке списка до завершения фильтрации. Тест ожидания исправлен через проверку конечного состояния; последующий полный прогон — 8/8. Исправлена и защита UI от записи результата отменённого запроса.

Точные итоги последнего backend-прогона и время: `runtime/pytest.xml`. Итоги браузера: `runtime/playwright-results.json`. Контрастный официальный сценарий: `runtime/official-verification.json`.

## Не проверено / блокировки

- Настоящая LLM и смысловое качество ответа: нет API key, endpoint, подтверждённого model ID/протокола и тарифов. Ни одного реального LLM-вызова не сделано. HTTP-стабы не заменяют эту проверку.
- Docker Compose build/up и ARM64-образ: Docker/Podman/Colima отсутствуют. Подготовленная конфигурация не объявляется проверенной сборкой.
- Публичный URL: нет размещённого Python/PostgreSQL сервера и подтверждённых прав на публикацию исходных данных. Не размещался неработающий статический макет.
- GitHub remote и доступ alfa-hack-2026: локальный Git есть, gh и подключённого GitHub нет. Найден и предложен соответствующий плагин; его подключение требует пользователя.
- Промышленная безопасность, SSO, DNS pinning, нагрузочные характеристики и экспертные ranking/LLM-метрики не заявляются проверенными.

Известное некритичное предупреждение тестов: текущая Starlette помечает использование HTTPX в TestClient как deprecated; контрактные тесты проходят. Оно не скрыто и не трактуется как ошибка приложения.
