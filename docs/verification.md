# Проверки

| Проверка | Результат |
|---|---|
| Backend | 54 теста |
| Миграции | Применение на пустой схеме PostgreSQL |
| Frontend | TypeScript и production-сборка Vite |
| Браузер | 8 сценариев desktop/mobile с официальными данными |
| Docker | Сборка образа, запуск Compose, healthcheck и HTTP smoke |
| Источники | Импорт официальных CSV и PDF, обновление двух RSS |

Текущий результат каждого коммита доступен в [GitHub Actions](https://github.com/OG1221/alfa-insight/actions/workflows/verify.yml). Отчёты прикреплены к запуску.

## Что покрывают тесты

Backend: импорт и конфликты данных, разграничение доступа, ранжирование, агентные шаги, повторный поиск, проверка цитат и чисел, бюджет LLM, ошибки провайдера, уточняющий диалог и загрузка файлов.

Браузер: выбор компании, профиль, фильтры, разбор, источники, журнал действий, новая новость, отказ небезопасной ссылки, официальный доступ и поиск по документам. В CI два сценария официального набора пропускаются: закрытые данные в репозиторий не включены. Остальные шесть проходят на синтетических данных.

Контейнерный smoke проверяет новую новость, персонализацию для двух компаний, сохранение журнала и отказ доступа к закрытым данным.

## Границы проверки

В тестах LLM используется управляемый провайдер. Это проверка интеграции и обработки ошибок, а не качества настоящей модели. Для реального API предусмотрен `scripts/check_llm.py --run`.

Проверка ссылок и цитат не заменяет смысловую оценку. План экспертной разметки и расчёта метрик находится в `quality.md`.
