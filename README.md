# Альфа Инсайт

Сервис персональной новостной аналитики для бизнеса. Он сопоставляет события с отраслью, продуктами, географией и связями компании, находит материалы банка и собирает разбор с рисками, возможностями и ссылками на источники.

## Запуск

Нужны Docker и Docker Compose.

```sh
docker compose up --build -d
```

- Приложение: http://127.0.0.1:8000
- Документация API: http://127.0.0.1:8000/api/docs
- Проверка доступности: http://127.0.0.1:8000/api/health

При первом запуске применяются миграции и загружаются три синтетические компании. Настройки можно изменить в `.env`; шаблон находится в `.env.example`. Для другого порта задайте `APP_PORT`.

Остановить приложение: `docker compose down`. Данные PostgreSQL остаются в volume. Команда `docker compose down -v` удаляет базу.

Запуск без Docker на Windows описан в [docs/windows.md](docs/windows.md).

## Как проверить

1. На главной странице выберите компанию и роль пользователя.
2. Откройте профиль: отрасль, продукты, география и связи используются при отборе событий.
3. Откройте новость из ленты. В разборе показаны основания релевантности, последствия, действия и банковские материалы.
4. Во вкладках «Источники» и «Как выполнен анализ» проверьте цитаты и выполненные инструменты.
5. Смените компанию и откройте то же событие — оценки и выводы зависят от её признаков.
6. Добавьте собственную новость через «Новое событие».

Подробный [сценарий проверки](docs/demo-script.md). Сопоставление с критериями кейса — [docs/criteria-compliance.md](docs/criteria-compliance.md).

## Данные и доступ

Без токена доступны синтетические компании. Доступ к официальным профилям, банковским документам и импорту открывается в «Настройках стенда» по токену администратора.

| Параметр | Значение по умолчанию |
|---|---|
| Демонстрационный токен | `alfa-local-demo` |
| Токен администратора | `alfa-local-admin` |
| Роли аналитики | финансовый директор, казначейство, генеральный директор, главный бухгалтер |

Это учётные данные локального стенда. Перед внешним размещением их нужно заменить.

Официальные материалы загружаются отдельно:

- [Данные компаний](https://drive.google.com/drive/folders/1Ep8wWoEHTg5Q8kwrLx2j_xFyxGUEVxFq)
- [Аналитика банка](https://drive.google.com/drive/folders/15xZTLF1lZ65p6o5xpNA_fRbxjoV-UlG1)

Поместите файлы в `data/private`, затем выполните:

```sh
docker compose exec app python scripts/import_data.py --directory data/private --pdf
```

CSV импортируются в порядке: компании, связи, платежи. PDF обрабатываются локальным OCR. Повторный импорт неизменных файлов пропускается по хешу. Официальные материалы и ключи не включены в репозиторий или образ.

Описание полей, конфликтов и ограничений — [docs/data-report.md](docs/data-report.md).

## Анализ и LLM

Агент получает профиль и событие, проверяет связи, ищет связанные новости и банковские материалы, оценивает достаточность доказательств. При необходимости он расширяет поиск. Модель формирует черновик, может запросить дополнительный поиск и выполняет финальную проверку. План, инструменты и источники сохраняются в базе.

По умолчанию `LLM_MODE=disabled`: работают поиск, ранжирование и разбор по правилам. Для генеративных выводов и уточняющих вопросов нужен API разрешённой модели. Реальная LLM-интеграция пока не проверена. Порядок подключения — [docs/llm-setup.md](docs/llm-setup.md).

Цитаты, ссылки и числа проверяются автоматически. Смысловая поддержка выводов требует отдельной оценки. Неизвестные остатки, задолженность и рыночная доля не подменяются предположениями.

## Настройки

| Переменная | Назначение |
|---|---|
| `APP_PORT` | Порт приложения, по умолчанию `8000` |
| `POSTGRES_PASSWORD` | Пароль базы в Docker Compose |
| `DATABASE_URL` | Подключение к PostgreSQL при запуске без Compose |
| `DEMO_MODE` | Анонимный доступ к синтетическим данным |
| `DEMO_TOKEN`, `ADMIN_TOKEN` | Токены доступа |
| `LLM_MODE` | `disabled` или `production` |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | Адрес API, ключ и технический ID модели |
| `LLM_APPROVED_NAME`, `LLM_PROTOCOL` | Разрешённая модель и протокол адаптера |
| `LLM_INPUT_RUB_PER_MILLION`, `LLM_OUTPUT_RUB_PER_MILLION` | Тарифы для учёта бюджета |
| `LLM_DAILY_BUDGET_RUB` | Дневной бюджет, не более 500 рублей |
| `AGENT_MAX_STEPS`, `AGENT_TIMEOUT` | Ограничения шагов и времени анализа |

Полный список — в `.env.example` и `backend/app/config.py`.

## Архитектура

React + TypeScript → FastAPI → PostgreSQL. Импорт, ранжирование, поиск и агентная логика реализованы в backend. FastAPI также раздаёт собранный интерфейс; отдельный frontend-сервер нужен только для разработки.

```text
backend/app/       API, агент, поиск, ранжирование и импорт
backend/alembic/   Миграции базы
backend/tests/     Backend-тесты
frontend/src/      Интерфейс
frontend/e2e/      Браузерные сценарии
config/           Веса ранжирования
data/synthetic/   Тестовые данные
eval/             Шаблон разметки качества
scripts/          Импорт и проверка приложения
docs/             Техническая документация
```

[Устройство агента и разграничение доступа](docs/architecture.md).

## Тесты

Backend-тесты можно запустить в работающем контейнере:

```sh
docker compose exec app python -m pytest backend/tests -q
```

Для сборки интерфейса и браузерных тестов нужны Node 22+ и pnpm 11.25.0:

```sh
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
pnpm --dir frontend exec playwright install chromium
pnpm --dir frontend test:e2e
```

Backend-тесты работают в отдельных временных схемах. Браузерные тесты ожидают запущенное приложение. Если официальный набор не импортирован, задайте `SKIP_OFFICIAL_E2E=1`.

[Результаты и состав проверок](docs/verification.md) · [GitHub Actions](https://github.com/OG1221/alfa-insight/actions/workflows/verify.yml) · [Метрики качества](docs/quality.md).

Зависимости закреплены lock-файлами. Перечень сторонних компонентов находится в `THIRD_PARTY_NOTICES`.
